## 🎯 Цель документа

Создать систематический подход к исследованию и документированию структуры реальных данных из 1С, исключающий предположения и догадки. Обеспечить получение точного понимания структуры данных через последовательный анализ: структура → примеры → паспорт документа → каталог сущностей.

## 🔍 Принципы исследования данных

### ✅ Основные принципы

1. **"Сначала сырье"** - всегда начинать с просмотра реальной структуры данных
2. **"Никаких предположений"** - не использовать знания о 1С, только факты из данных
3. **"Итеративный подход"** - структура → примеры → анализ → выводы
4. **"Документирование"** - вести паспорт каждого исследуемого документа
5. **"Кросс-проверка"** - проверять связи между таблицами реальными операциями
6. **"Анализ кода"** - всегда искать ошибки в коде извлечения данных
7. **"Проверка методов"** - валидировать качество извлечения данных

### ❌ Запрещенные действия

- Использование знаний о 1С без проверки в данных
- Предположения о назначении полей без анализа содержимого
- Выводы о структуре без просмотра примеров данных
- Работа с данными без предварительного анализа структуры
- Игнорирование ошибок в коде извлечения данных
- Продолжение работы с неисправленным кодом
- **Установка лимитов по умолчанию** без явного указания
- **Фильтрация данных** без анализа полной картины
- **Игнорирование ошибок** без их анализа
- **Предположения о структуре** без проверки в данных
- **Фокус только на "успешных" записях** без анализа исключений
- **Использование предварительных знаний** без валидации в данных
- **🚨 САМООБМАН В BLOB ОБРАБОТКЕ:**
  - Возврат `None` или "пустое поле" когда не понимаем тип BLOB
  - Скрытие реального состояния данных от анализа
  - Не документирование того, что именно не смогли извлечь
  - Ложные утверждения о "пустых" полях без проверки
  - Игнорирование неизвестных типов BLOB объектов

## 🧠 КОГНИТИВНЫЕ ИСКАЖЕНИЯ AI АГЕНТА В ИССЛЕДОВАНИИ ДАННЫХ

### 🚨 КРИТИЧЕСКИЕ ИСКАЖЕНИЯ И ИХ ПРИЧИНЫ

#### **1. SURVIVORSHIP BIAS (Ошибка выжившего)**
**Суть:** AI агент видит только "выжившие" данные, не замечая "мертвые" или скрытые

**Причины возникновения:**
- **По умолчанию ставится limit** → не видишь полную картину данных
- **Явно указываешь поля и документы** → не видишь неожиданные паттерны  
- **Фильтрация по известным критериям** → упускаешь аномалии
- **Анализ только "успешных" записей** → не видишь ошибки и исключения

**Примеры в коде:**
```python
# ❌ ОШИБКА: Скрытый лимит
if limit is None:
    actual_limit = table_info["size"]  # Может быть 0 или неправильным!

# ❌ ОШИБКА: Анализ только первых записей  
sample_size = min(10, len(table))  # Упускаешь 90% данных!

# ❌ ОШИБКА: Фильтрация по известным полям
for field in known_fields:  # Не видишь новые поля!
```

#### **2. CONFIRMATION BIAS (Предвзятость подтверждения)**
**Суть:** AI агент ищет данные, подтверждающие его гипотезы, игнорируя противоречащие

**Причины возникновения:**
- **Предположения о структуре 1С** → ищешь только ожидаемые поля
- **Знания о бизнес-логике** → не видишь нестандартные случаи
- **Ожидание определенных типов данных** → игнорируешь аномалии
- **Фокус на "правильных" записях** → не анализируешь ошибки

**Примеры в коде:**
```python
# ❌ ОШИБКА: Предположения о типах полей
if field_name.startswith("_FLD"):  # Предполагаешь что это BLOB
    # Но может быть обычное поле!

# ❌ ОШИБКА: Игнорирование ошибок
except Exception as e:
    print(f"Ошибка: {e}")  # Продолжаешь, не анализируя причину
    continue
```

#### **3. ЛОЖНАЯ MENTAL MODEL**
**Суть:** Формируется неверное представление о структуре данных

**Причины возникновения:**
- **Анализ неполных данных** → неправильная модель
- **Игнорирование исключений** → неполная картина
- **Фокус на "типичных" случаях** → упускаешь edge cases
- **Предположения без проверки** → ложные выводы

```python
def analyze_complete_dataset(table):

    all_records = []
```

#### **2. ПРИНЦИП "НИКАКИХ ПРЕДПОЛОЖЕНИЙ"**
```python
# ✅ ПРАВИЛЬНО: Анализ без предварительных знаний
def discover_field_types(field_value):
    """Определяет тип поля на основе данных, не предположений"""
    if isinstance(field_value, bytes):
        return "bytes"
    elif isinstance(field_value, str):
        return "string"
    # НЕ предполагаем тип по имени поля!
```

#### **3. ПРИНЦИП "АНАЛИЗ ИСКЛЮЧЕНИЙ"**

```python
# ✅ ПРАВИЛЬНО: Специальный анализ ошибок и исключений
def analyze_errors_and_exceptions(data):
    """Анализирует ошибки и исключения для полной картины"""
    errors = []
    exceptions = []
```

### 🔍 ПРОТОКОЛ "АНТИ-ИСКАЖЕНИЯ"

#### **Этап 1: Полный анализ без фильтров**
1. **Загрузить ВСЕ данные** без лимитов и фильтров
2. **Показать полную структуру** (все поля, все типы)
3. **Проанализировать ВСЕ записи** (включая пустые и ошибочные)
4. **Найти аномалии и исключения** (не игнорировать их)

#### **Этап 2: Множественная валидация**
1. **Использовать разные методы** анализа одних и тех же данных
2. **Сравнивать результаты** разных подходов
3. **Искать противоречия** между методами
4. **Анализировать различия** для понимания причин

#### **Этап 3: Анализ ошибок и исключений**
1. **Собирать ВСЕ ошибки** (не игнорировать их)
2. **Анализировать паттерны ошибок** для понимания структуры
3. **Изучать edge cases** и аномальные данные
4. **Документировать исключения** как важную информацию

#### **Этап 4: Кросс-проверка с независимыми источниками**
1. **Проверять находки** через разные инструменты
2. **Сравнивать с документацией** (если есть)
3. **Валидировать через экспертов** (если доступны)
4. **Тестировать гипотезы** на новых данных

```python
# ✅ ПРАВИЛЬНО: Случайная выборка для избежания систематических ошибок
def random_sampling_analysis(data, sample_size=1000):
```

```python
# ✅ ПРАВИЛЬНО: Анализ данных в разные временные периоды
def temporal_analysis(data, time_field):
    """Анализирует данные в разные временные периоды"""
    time_periods = data[time_field].dt.to_period('M').unique()
    
    for period in time_periods:
        period_data = data[data[time_field].dt.to_period('M') == period]
```

#### **8. ПРИНЦИП "КРАЙНИЕ СЛУЧАИ"**
```python
# ✅ ПРАВИЛЬНО: Специальный анализ крайних значений
def extreme_cases_analysis(data, numeric_fields):
    """Анализирует крайние значения для понимания границ данных"""
    extreme_cases = []
    
    for field in numeric_fields:
        # Находим максимальные и минимальные значения
        max_value = data[field].max()
        min_value = data[field].min()
        
        # Анализируем записи с крайними значениями
        extreme_cases.extend(data[data[field] == max_value])
        extreme_cases.extend(data[data[field] == min_value])
    
    return analyze_extreme_cases(extreme_cases)
```

### 🔍 ПРОТОКОЛ "ПРЕДОТВРАЩЕНИЯ ЛОЖНЫХ MENTAL MODELS"

#### **Этап 1: Множественные гипотезы**
1. **Сформулировать 3-5 альтернативных гипотез** о структуре данных
2. **Искать подтверждения для каждой гипотезы** независимо
3. **Сравнивать силу доказательств** для разных гипотез
4. **Выбирать гипотезу с наибольшим количеством подтверждений**

#### **Этап 2: Поиск противоречий**
1. **Специально искать данные**, противоречащие основной гипотезе
2. **Анализировать причины противоречий** для корректировки модели
3. **Документировать исключения** как важную информацию
4. **Обновлять модель** на основе найденных противоречий

#### **Этап 3: Временной анализ**
1. **Анализировать данные в разные периоды** времени
2. **Искать изменения в структуре** данных со временем
3. **Выявлять тренды и аномалии** в разных периодах
4. **Документировать эволюцию** структуры данных

#### **Этап 4: Крайние случаи**
1. **Специально анализировать крайние значения** в данных
2. **Изучать аномальные записи** для понимания границ
3. **Анализировать edge cases** для полноты модели
4. **Документировать границы** применимости модели

### 🚨 КРИТИЧЕСКИЕ ПРИЗНАКИ ЛОЖНОЙ MENTAL MODEL

#### **Признаки, что модель неверна:**
- **Большое количество исключений** (>10% от общего объема)
- **Противоречия между разными методами** анализа
- **Невозможность предсказать** поведение новых данных
- **Постоянные ошибки** в интерпретации данных
- **Необходимость постоянных** "исправлений" модели

#### **Действия при обнаружении ложной модели:**
1. **Полностью пересмотреть** все предположения
2. **Начать анализ заново** с принципа "никаких предположений"
3. **Использовать только факты** из данных
4. **Документировать процесс** пересмотра модели
5. **Валидировать новую модель** независимыми методами

## 🔧 Анализ кода и поиск ошибок

### 🎯 Приоритет 1: Поиск ошибок в коде

**Перед началом исследования данных ОБЯЗАТЕЛЬНО:**

2. **Анализ логики извлечения:**
   - Проверить правильность определения типов полей

   - Проверить обработку исключений

3. **Анализ качества извлечения:**
   - Проверить извлечение BLOB данных
   - Проверить извлечение числовых полей
   - Проверить извлечение дат и строк

### 🚨 Критические ошибки для поиска

#### **1. Ошибки типов данных:**
- `'>' not supported between instances of 'str' and 'int'`
- `'<' not supported between instances of 'str' and 'int'`
- `'==' not supported between instances of 'str' and 'int'`

#### **2. Ошибки атрибутов:**
- `'str' object has no attribute 'isoformat'`
- `'NoneType' object has no attribute 'value'`
- `'bytes' object has no attribute 'decode'`

#### **3. Ошибки итераторов:**
- `generator raised StopIteration`
- `'generator' object is not subscriptable`
- `'iterator' object has no attribute 'next'`

#### **4. Ошибки импорта:**
- `ModuleNotFoundError: No module named 'utils'`
- `ImportError: cannot import name 'BlobProcessor'`
- `AttributeError: module has no attribute 'BlobProcessor'`

### ✅ Протокол исправления ошибок

#### **Этап 1: Идентификация ошибки**
1. Запустить код и получить ошибку
2. Проанализировать стек вызовов
3. Найти точное место ошибки в коде
4. Определить тип ошибки

#### **Этап 2: Анализ причины**
1. Проверить типы данных в проблемном месте
2. Проанализировать логику сравнения/операции
3. Найти корневую причину ошибки
4. Определить правильное решение

#### **Этап 3: Исправление**
1. Применить правильное решение
2. Добавить проверки типов
3. Улучшить обработку ошибок
4. Протестировать исправление

#### **Этап 4: Валидация**
1. Запустить код без ошибок
2. Проверить качество извлечения
3. Сравнить результаты до/после
4. Документировать изменения

### 🧠 Лучшие стратегии анализа кода

#### **1. Стратегия "Сначала ошибки":**
- **Принцип:** Всегда начинать с поиска и исправления ошибок
- **Метод:** Запустить код, получить ошибки, исправить их
- **Результат:** Работающий код без ошибок

#### **2. Стратегия "Статический анализ":**
- **Принцип:** Анализировать код без выполнения
- **Метод:** Искать проблемные паттерны с помощью grep, regex

```python
# Проверка связей между таблицами
def check_relationships(df1, df2, key_field):
    """Проверяет связи между таблицами"""
    common_values = set(df1[key_field]) & set(df2[key_field])
    print(f"Общих значений в {key_field}: {len(common_values)}")
    return common_values

# Анализ ссылочных полей
def analyze_references(df, ref_field):
    """Анализирует ссылочные поля"""
    ref_values = df[ref_field].value_counts()
    print(f"Топ-10 значений в {ref_field}:")
    print(ref_values.head(10))
```
