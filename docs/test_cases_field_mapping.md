## 🧪 ТЕСТ-КЕЙСЫ ДЛЯ ПРОВЕРКИ МАППИНГА ПОЛЕЙ

### **ТЕСТ-КЕЙС 1: ПРОВЕРКА ТЕРМИНАЛЬНОГО ВЫВОДА**
**Цель:** Убедиться, что в терминале отображаются реальные названия полей, а не field_X

**Шаги:**
1. Запустить `extract_all_available_data.py`
2. Проверить вывод схемы данных
3. Убедиться, что поля отображаются как `_FLD4229 (Основное описание операции (BLOB))` вместо `field_0`

**Ожидаемый результат:**
- В терминале: `_FLD4229 (Основное описание операции (BLOB)): bytes (BLOB)`
- НЕ в терминале: `field_0: bytes (BLOB)`

### **ТЕСТ-КЕЙС 2: ПРОВЕРКА BLOB ДЕКОДИРОВАНИЯ**
**Цель:** Убедиться, что BLOB поля декодируются и показывают читаемое содержимое

**Шаги:**
1. Запустить извлечение данных
2. Проверить вывод BLOB полей
3. Убедиться, что содержимое декодировано (не hex)

**Ожидаемый результат:**
- BLOB содержимое: `"Флор на Магазин ПЦ022 (Чеховский) от 16.08.2015"`
- НЕ BLOB содержимое: `<94 bytes>: 464c4f520000000000000000...`

### **ТЕСТ-КЕЙС 3: ПРОВЕРКА ОБНОВЛЕНИЯ ДОКУМЕНТАЦИИ**
**Цель:** Убедиться, что маппинг записан в 1c-structure-mapping-analysis.md

**Шаги:**
1. Открыть `prostosvet.ru/1c-structure-mapping-analysis.md`
2. Найти секцию с маппингом полей
3. Проверить соответствие реальным данным

**Ожидаемый результат:**
- Документация содержит актуальный маппинг
- Поля соответствуют реальным данным из базы

### **ТЕСТ-КЕЙС 4: ПРОВЕРКА КРОСС-ВАЛИДАЦИИ**
**Цель:** Убедиться, что данные в Parquet соответствуют терминальному выводу

**Шаги:**
1. Сравнить поля в Parquet файле
2. Сравнить с терминальным выводом
3. Проверить соответствие маппингу

**Ожидаемый результат:**
- Поля в Parquet: `field__FLD4229`
- Поля в терминале: `_FLD4229 (Основное описание операции (BLOB))`
- Маппинг: `_FLD4229: "Основное описание операции (BLOB)"`
